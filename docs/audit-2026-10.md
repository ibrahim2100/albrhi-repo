would is listed under "Open" for the owner to decide.

## Open — needs a decision

### 1. YouTube Music sends non-Latin lyrics to Google by default (privacy rule)

`lyricsRomanization` defaults to **on** (`Tweak.x:104`, `YTMULyricsManager.m:364`, `TranslationSettingsController.m:131`).
For lyrics whose script needs it (`needsRomanizationForText:`), each line goes by GET to
`translate.googleapis.com/translate_a/single?client=gtx…` — no key, no account. The lines identify the song.
CLAUDE.md §2 says every feature that tells an outside service what someone is listening to or watching is **off until turned
on and says so on its own row**; lyric *sources* are excused there ("on because asked for by name") and translation is off
by default, but romanization is neither. A switch exists (in the lyrics overlay), so this is a default and not a hidden path.
**Recommendation:** default off, and say on the row that it contacts Google. Alternative: keep it on and amend §2 and the row
to say so — the owner's call, because an Arabic-speaking listener of a Japanese or Korean song probably wants it on.

### 2. `extra-debs/com.junesiphone.designer_1.5.5_iphoneos-arm64e-1.deb` (28 MB)

A third-party tweak package committed to the repository and, by the "drop a `.deb` here" rule, published from the source.
Two questions only the owner can answer: is redistributing it permitted, and does it belong in this history (it is the
single largest object in a 1.1 GB `.git`). If it is a local convenience it should be ignored and removed from the tree; history
would need a rewrite to shrink, which is its own decision.

### 3. Instagram OLED theme hooks are installed for everyone

`OledTheme.xm` hooks `-setBackgroundColor:` on `UIView`, `UITableView` and `UICollectionView` unconditionally; the switch is read
once at launch (`dispatch_once`) and the setting already says it needs a restart. For anyone with OLED off, every background
colour set in the app pays a hook call and a branch. Moving the three hooks into a `%group` initialised only when the switch was
on at launch makes the cost zero for them. Behaviour-neutral, small, needs an Instagram release. **Recommendation: do it next time
Instagram is touched.**

### 4. Dead code, remove on each tweak's next release

- Watch: `SCIWClassReport`, `SCIWAnswerReport`, `SCIWVersionReport` (`Diagnostics/SCIWDiagnostics.m`) and `SCIWNanoProbeReport`
  (`Sync/SCIWNanoSync.m`) — declared, defined, never called. CLAUDE.md §4.4 says such probes are off unless switched on; these are
  off because nothing reaches them. Watch is its own package, so removal is a Watch release.
- YouTube Music: `SCIYTMInstallAttempts()` — a counter nothing reads. (§4.4 once found exactly this: a counter that is kept and not shown.
  Either put it on the report or delete it.)
- Spotify: `SCILocalized` in `Localization/SCILocalize.m` has no caller (unpublished tweak).
- **Not dead, despite the scan:** `SCIPanelRootController` is named in the panel's `Info.plist` and `AlbrhiPanel.plist`.

### 5. 178 empty `@catch` blocks

`@catch (…) { }` swallows an `NSException` and says nothing. Most are around KVC-style reads that predate `SCISafeValueForKey`
(CLAUDE.md §4.2: `@catch` does not make a probe safe anyway), and 153 of the `@try`s are in NextUp's upstream code, which this port
keeps diffable on purpose. Not worth a sweep. A better use: when a bug report says "silently does nothing", this is where to look.

### 6. CI hygiene

- Third-party actions are pinned to a major tag (`softprops/action-gh-release@v2`, `actions/*@v4`). The release job has
  `contents: write`; pinning `softprops/action-gh-release` to a commit SHA is the standard hardening.
- Five "manual build, writes nothing" workflows (`buildtweak` — which is the Instagram one —, `buildyoutube`, `buildtwitter`,
  `buildtiktok`, `buildpanel`) are ~1,000 lines of near-duplicate YAML, one per tweak. One workflow taking the tweak name as an input
  would replace them. Nothing is broken, it is maintenance weight.
- The pre-commit hook (`bash tools/install-hooks.sh`) is not installed in this clone; it would have caught nothing in this session
  (the checks were run by hand) but it removes the possibility of forgetting.

### 7. Repository size

`.git` is 1.1 GB (pack 896 MB) with two leftover `tmp_pack_*` files from an interrupted write. `git gc` removes the garbage and is safe;
shrinking the history (the 28 MB `.deb`, earlier IPAs or dumps if any ever went in) needs `git filter-repo` and a force-push, which this
project has never done and should not do without a decision and a backup.

### 8. User-typed API keys sit in the app's preferences (YouTube Music translation)

`translationApiKey_<provider>` is stored in `NSUserDefaults` under the `YTMUltimate` dictionary; the row is masked (`"secure": YES`), the
storage is not. The data lives inside Music's own container and is only sent to the provider the user chose, so this is an accepted
tradeoff for a jailbreak tweak, not a leak — but the Keychain is the proper place and the settings backup file
(`SCIPanelBackup`) is worth checking for whether it includes these keys.

## Observations (no action)

- **Hosts the source names**, by count: instagram.com, youtube.com, github.com (issue filing, update check), openai.com,
  anthropic.com and generativelanguage.googleapis.com (translation, the user's own key), music.youtube.com, translate.googleapis.com
  and translate.google.com (see Open 1), i.ytimg.com, sponsor.ajay.app (SponsorBlock, off by default), lrclib.net, genius.com,
  apic-desktop.musixmatch.com and interface.music.163.com (lyrics sources), tikwm.com (TikTok external HD, off by default). The rest are
  test fixtures or link-cleaning test strings (`example.invalid`, `notinstagram.com`).
- **The `AIza…` strings** in `SCIYTStreamAPI.m` and `YTMUInnerTubeDescriptionFetcher.m` are YouTube's own public InnerTube client keys, the
  ones every client sends; they are not credentials.
- **`NSLog`**: 25 calls in Spotify (behind its debug switch since 0.2.5), six in YouTube, five in YouTube Music, two or fewer elsewhere.
- **Files over 1,500 lines**: `SCITTMedia.m` (1,607), `NUNextUpRowView.m` (1,606, upstream), `SCITTButton.x` (1,566). Large, coherent, no action.
- **Generic hooks read and judged acceptable**: X's `NSURLSession` hook sits in a group attached only when the switch was on at launch;
  YouTube's `_ASDisplayView -didMoveToWindow` stands aside until the app is active and documents why (a launch once died there); the
  `UIWindow` hooks in the settings gestures and the copy feature only attach a recogniser or watch touches on windows already marked.
- **Host tests are not equally deep**: the transport, lyrics, deleted-messages log, copy rules, timeline filter and link ranking have them;
  the DASH remuxer and TikTok's link comparator, the two most expensive bugs' homes, still do not (§3.5 says why).
